# 方法知识库对照实验：加知识 vs 不加知识

```
date            2026-10-16
model           gpt-4o-mini（CODING_AGENT_MODEL）
papers          2106.09685（LoRA）、2006.11239（DDPM）
runs            每篇论文 × 每种配置各 2 轮（第 1 轮不含修订，第 2 轮含“审查 → 修订一次 → 再审查”）
cost            约 $0.03（两轮合计）
judgement       问题相关性与代码正确性由 Claude Code 阅读输出后人工判断，不是自动评分
runner          evaluation/runners/run_method_notes_ab.py（第 2 轮的流程）
```

样本很小（每种配置 4 次运行），只能作为方向性证据。

## 1. 提给学习者的问题：稳定改进

方法评估会列出“论文没写清、需要学习者决定”的实现选择。统计这些问题中，关于方法机制本身（而不是玩具规模参数）的比例：

| | 加知识 | 不加知识 |
|---|---|---|
| 关于机制本身的问题 | **12/12** | 7/12 |

- 加知识：LoRA 两轮都问了“对哪些权重矩阵加适配器”；DDPM 两轮都问了“模型预测噪声、x0 还是 v”。
- 不加知识：近一半问题是“合成矩阵取多大”“输入数据取多大”“网络有多大”这类不影响机制的参数。

## 2. 生成代码的正确性：没有可靠改进

| 运行 | DDPM 前向加噪（应为 sqrt(ᾱ_t)·x0 + sqrt(1−ᾱ_t)·ε） |
|---|---|
| 第 1 轮 加知识 | 正确 |
| 第 1 轮 不加知识 | 错误，用了单步的 β_t |
| 第 2 轮 加知识 | **错误**，用了单步的 β_t |
| 第 2 轮 不加知识 | 错误 |

第 1 轮看起来是知识库修正了这个错误，第 2 轮加了知识依然写错，审查步骤也没有发现。结论：把知识放进 prompt，并不能让 gpt-4o-mini 稳定地写对代码。

LoRA 的初始化（A 随机、B 为 0）和 α/r 缩放在 4 次运行里都写对了，但论文原文本身就写明了这些细节，所以知识库在这里没有增量。

## 3. 实验暴露的、与知识库无关的问题

- **随机数冒充梯度**：两轮 LoRA 的 4 份代码全部用 `np.random.randn` 当梯度，审查步骤都没有指出。
- **恒真自检**：一份代码写了 `np.allclose(W0, W0)`。
- **没有训练步骤**：DDPM 的代码只写了一句注释“这里应该做梯度下降”。

据此新增了确定性的代码检查（`coding_practice.quality_issues`）：恒真比较，以及梯度或损失的表达式里出现随机数。第 2 轮中，检查发现的随机梯度在修订后从直接赋值消失了，但模型把随机数挪进了梯度公式内部，绕过了第一版规则；规则随后扩大到“表达式内部任何位置”。“没有训练步骤”目前查不出来。

## 4. 结论

- 知识库可靠地改善了“向学习者确认实现方案”这一步，这是它当前确定的价值。
- 代码正确性的瓶颈在模型能力，不在知识。可靠的改进需要实际运行自检（沙箱目前未在线上启用），或者在审查步骤换用更强的模型（通过 `MODEL_ROUTES` 可以只改这一步）。
